Can Shared Patterns Cut AI Memory by Four-Fifths Without Losing the Answer?

FractiAI Research ? November 3, 2026

A household that keeps eight photocopies of the same lease in eight drawers pays for paper it never reads. A clinic that reprints the full patient chart for every specialist desk fills shelves while the useful difference?today?s note?fits on a sticky. Modern AI systems often behave like those offices: the same organizational pattern shows up as source, parse, index, embedding, cache, intermediate, and context copy. Tiny Gateway asks a blunt question. If you keep the pattern once, store only what makes each expression different, and rebuild just the slice you need for the next job, can you cut about four-fifths of the resident memory bill without scrambling the answer?

The problem of paying rent on duplicates

A lot of cost is paying rent on duplicated resident state so the same organizational pattern can be served many times. Memory is not only ?how big is the model.? For many serving stacks, a large share of resident bytes sits in KV-style context, retrieval caches, activations, indexes, and intermediate copies. Ordinary engineering squeezes each pile. Tiny Gateway proposes a deeper change of habit: treat many objects as rhymes?distinct expressions of a reusable organization called a Rhyming Template. The productized layer is named Tiny Footprint. Nested vectors carry relationships across scales. One originating story can fan out to eight connection nodes without eight full reprints.

If operators can deliver the same service with far less resident memory for that non-weight pile, they can pack more concurrent work per box, buy less memory per unit of AI service, and stretch limited accelerator supply further. An illustrative budget makes the ambition concrete: if model weights are fifteen percent of a normalized pie and stay put, an eighty percent total cut means roughly ninety-four percent of everything else must be shared away or reconstructed on demand.

What the lab actually measured

The suite first compares conventional full materializations against Tiny representations in process. Structured records sharing one template saved about fifty-four percent. Graphs that stopped embedding fat node dossiers inside every edge saved about eighty-two percent. Eight nodes sharing one story saved about eighty-six percent. A short cross-octave working set versus the full lattice saved about ninety-nine percent. An AI-context proxy that stored the long system prompt once saved about forty-nine percent. Aggregate reduction landed at about eighty-four point five percent?clear of the eighty percent gate?with exact reconstruction on primary and validation seeds.

Version 1.2 adds a live GPU chat-stack lab for Tiny Footprint on this laptop’s NVIDIA GeForce GTX 860M, now with latency as well as memory. Conventional mode duplicated system-pattern and KV-like buffers per session; Tiny Footprint kept one shared system pattern plus compact per-session state. Allocated device memory fell about eighty-one percent (288 to 54 MiB). nvidia-smi peaks fell about seventy-three percent (313 to 85 MiB). Sessions per non-weight mebibyte rose about twelve times. Turn materialization latency, timed with cuMemcpyHtoD on that card, fell from about forty-four milliseconds without Tiny Footprint to about four milliseconds with it—roughly eleven times faster—while session bring-up improved from about six to about three milliseconds. That is materialization traffic, not frontier model decode time. This GeForce uses GDDR; datacenter HBM is the operator analogue for the same duplicated-resident-state problem, not identical silicon. Experiments E1 through E9 passed nine of nine. Engine shelf seat fifty-two stays pinned.

Hypothesis under test

If Rhyming Templates and Tiny Footprint are more than slogans, then (1) the illustrative eighty percent model should be arithmetically coherent, (2) concrete workloads should show large measured savings where duplication is the disease, (3) reconstruction should stay exact where exactness is required, (4) a live GPU chat-stack proxy should show a device-memory cut, concurrency-density gain, and materialization latency that does not get worse?and preferably gets better?with Tiny Footprint, and (5) the engine shelf should open only when gates clear. The suite supports those claims inside its boundary.

What is new, and what might be next

What is newly framed here is the full stack as one falsifiable memory program plus a named product?Tiny Footprint?aimed at today?s expense and shortage pattern. Potential next steps include operator runs on true HBM accelerators against production serving binaries, multi-host Tiny Footprint, and template discovery that does not invent false rhymes. Parents splitting one school calendar already know the pattern: shared schedule plus household deltas, not eight reprinted binders.
