## Abstract

**Primary question.** Can FractiAI Tiny Gateway — Boundary Node → Recursive Tree → Golden Spiral scale bridge → Honeycomb Lattice → Wave–Node–Fq with explicit template binding — provide a reusable computational foundation for bounded language processing, high-rate multi-sensor fusion, and specialized agent pathways?

**Methods.** Node ESM suite · seed `20261104` · three-way language arms · assignment-required civilian synthetic airspace (6 sensors · 180 tracks · 80 steps · 86 400 observations · 18 anomalies) · optional Movebank+Kp historical secondary · stage-isolated template timing · ablations · E1–E8 gates.

**Findings (executed).** **E1–E8 = 8/8.** Language: Tiny Gateway **0.585** vs lightweight **0.377** and micro-Transformer **0.377**. Fusion primary: F1 **0.097** both pipelines (Δ **0**); Tiny Gateway ≈**1.17×** conventional runtime on full fixture. Template: warm e2e reuse **not** competitive with bare rebuild. Engine pin **not recommended**. Historical secondary (when available): F1 **0.261** both arms.

**Limitation.** Not ATC radar; not a frontier LLM; synthetic anomaly F1 is modest; template pathway overhead is a measured cost.

**Keywords:** Tiny Gateway Expedition; template binding; Wave–Node–Fq; civilian synthetic airspace; small language model; application companion.

## 1. Research motivation

Reusable structure — construct once, bind many times — is a standing FractiAI hypothesis. This expedition treats that claim as an experimental program across language, high-rate fusion, and template-stage accounting. It does **not** assume superiority. It builds, runs, measures, and reports failures with the same weight as wins.

A prior Leo Computational Lab companion (`synthobs-tiny-gateway-language-radar-2026-10`) preferred real Movebank+Kp fusion and withheld the 6×180×80 legend as unverified. This Expedition 001 **restores the assignment-required civilian synthetic fixture as a first-class arm**, while still reporting the historical secondary when sources exist, and still refusing to treat prior conflicting timing/memory figures as verified baselines.

---

## 2. Existing approaches and limitations

Conventional small neural language models (even micro-Transformers) retrain or recompute pathways when tasks shift. Lightweight rule/TF-IDF pipelines are fast but brittle. Multisensor trackers associate observations with nearest-neighbor or filter logic that does not expose reusable “templates” as first-class objects. Agentic stacks often wrap LLMs without a measured binding layer.

Limitations this program targets: (1) missing stage accounting (construct vs select vs bind vs execute); (2) silent substitution of ordinary graphs for named FractiAI architecture; (3) speedup claims without hardware/software receipts.

## 6. Experiment A — Small language model

**Arms:** lightweight TF-IDF/rules · pure-JS 2-layer micro-Transformer · Tiny Gateway templates.

**Capabilities probed:** intent, instruction interpretation, entity/relation extraction, structured retrieval, bounded QA, multi-step execution, context retention, paraphrase, unseen generalization, new-knowledge incorporation.

**Architectural roles (tested separately):** (1) language-processing architecture; (2) execution layer surrounding an LLM stub; (3) replacement for portions of neural inference; (4) reusable substrate for specialized agents.

**Results (primary seed):**

| Arm | Accuracy | Median latency (ms) | Size (bytes) | Train (ms) |
|-----|----------|---------------------|--------------|------------|
| Lightweight | 0.377 | ~0.02–0.05 class | ~12k | ~tens |
| Micro-Transformer | 0.377 | similar order | ~148k | ~tens |
| Tiny Gateway | **0.585** | similar order | ~13k | ~few |

Roles: all **ok**. Intent agreement gateway↔lightweight ≈ **0.40**. Interpretation: bounded organizational win on this corpus — **not** LLM replacement.

## 11. Novelty vs demonstrated performance

**Novel (architectural):** named Boundary→Tree→φ-spiral→Honeycomb→Wave–Node–Fq stack with explicit template binding, stage-isolated timing, dual fusion arms, and expedition trailhead.

**Demonstrated:** language accuracy edge on bounded corpus; fusion F1 parity on assignment synthetic; honest reuse-gate failure; runnable reproducibility package.

**Not demonstrated:** general intelligence; ATC-grade surveillance; GPU/energy advantage; ENGINE_SHELF readiness.

---

## 12. Limitations and next steps

1. Micro-Transformer ≠ HuggingFace SLM — upgrade when a local ONNX/HF path is authorized.  
2. Synthetic anomaly heuristics drive modest F1 — improve labeling without claiming ATC.  
3. Reduce Wave–Node + honeycomb overhead so warm reuse can compete with bare closures.  
4. Prioritize next: **Experiment C overhead reduction** (pathway-lite warm path) while keeping stage honesty.

---

## 13. Implications for future LLMs and agents

Tiny Gateway is best filed today as a **bounded execution and organization layer** that can surround stub/LLM calls and host specialized templates — not as a trained-model replacement. Further development is justified for organizational clarity and stage accounting; not justified for claiming compute supremacy on this harness.

## 14. Conclusions

Expedition 001 ships a working Tiny Gateway stack, three-way language comparison, assignment-scale civilian synthetic fusion, stage-isolated template benchmarks, ablations, and an honest mixed scoreboard. Further development should chase **reuse overhead**, not slogans.
